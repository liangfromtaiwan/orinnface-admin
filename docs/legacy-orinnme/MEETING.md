## Demo 順序(12〜15 分、7 step)

### Step 1 — ① 運営ダッシュボード(2 分)
**URL**:`/dashboard`(初期表示)

**話す**:
- 「OrinnFACE 全体の俯瞰用 dashboard」
- 4 KPI:再分析率 / 継続率 / ケア実行率 / 主観 vs AI 一致率
- 表情・疲労分布の stacked bar(過去 7 日)
- プラン推移:「**Premium が唯一の課金プランという理解で実装**」← 確認
- 提供先別利用状況 Table(行クリックで視点切替)

### Step 2 — ③ BtoB 切替(1 分)
**動作**:CompanySwitcher → 「企業X 株式会社」

**話す**:
- **隱私 Banner** 注目「集計のみ、個人情報非表示」
- Sidebar が 5 項 → 4 項に縮む(ユーザー 消える)
- 「個人を特定できる情報は一切表示しない」規格要件の落地

### Step 3 — ② OEM 切替(1 分)
**動作**:CompanySwitcher → 「店舗A 美容サロン」

**話す**:
- 自家 badge「🏪 店舗A 美容サロン」(タイトル右)
- KPI 数字が ① より明らかに小さい(filter 効いている証拠)
- 「提供先別利用状況」が消える(自分しかいない)

### Step 4 — 警告色実装(2〜3 分)【規格 3-1 重点】
**動作**:
1. ① 視点に戻す
2. Sidebar 「ユーザー」
3. 4 件の赤い行(佐藤一郎 / 吉田大輔 / 林啓介 / 山下翔太)
4. 佐藤一郎 をクリック → `/users/3`
5. 「全行動履歴」までスクロール
6. 赤い row を指す

**話す**:
- 「規格書 3-1『行を赤くする + 警告アイコン』を実装しました」
- 「『行』は履歴の各レコード単位と解読しました」
- 「主観疲労と AI 判定の差が 2 段階以上 → 赤背景 + 警告 Badge」
- ❗ **「この解読、合っていますか?」と主動的に確認**

### Step 5 — コンテンツ分析(2 分)【規格 3-2】
**動作**:Sidebar 「コンテンツ分析」

**話す**:
- 4 KPI:動画本数 15 / 累計視聴 407 件 / 平均完遂率 74% / 再分析率 37%
- **動画尺別 完遂率 Bar Chart**(規格 3 章直接指定)
- 6 段階 bucket(30 秒 〜 5 分+)、前 3 段は既存 catalog、後 3 段は将来予約
- 完遂率は尺が長くなるほど下がる(30s→93%, 60s→79%, 2 分→53%)
- 人気動画 Ranking で具体的な動画名と KPI
- ② OEM / ③ BtoB に切替して filter 確認(b2b は集計のみで個人情報無し)

### Step 6 — ステータス(2 分)【規格 3-3】
**動作**:Sidebar 「ステータス」

**話す**:
- 4 KPI:Premium 数 5 / 純増 +1 件 / チャーン率 25% / 変更総件数 7 件
- 「率 + 件数」併記表示(小規模 mock で誤解を避けるため)
- プラン構成 推移(Stacked Area Chart、30 日)
- プラン変更ログ(降順、種別 Badge)
- ② OEM 切替 → 自社のみ(Yumi 視点で純増 -1 / チャーン 50% も見せる、要注目シナリオ)
- ③ BtoB は自動 Dashboard 転送(個別社員の課金状態は商業意義無し、規格にも記載なし)

### Step 7 — DEMO.md の確認事項(2〜3 分)
DEMO.md「規格書について確認したいこと」までスクロールし、5 項目逐次:

1. ✅ 警告色の実装位置(Step 4 で実演済み)
2. 全体コンディションスコアの定義
3. ステータス / コンテンツ分析画面の内容 ← Step 5-6 で実装済みを見せた、確認のみ
4. 提供先の権限境界(現 client-side のみ)
5. プラン推移の粒度

## Fallback 計畫

### production URL が開けない
1. localhost:5173 でデモ続行
2. dev server も死んでいる:`npm run dev` 再起動
3. 全滅:VS Code でソース + DEMO.md を画面共有

### デモ中に重大 bug 発見
1. 当場で修正しようとしない、慌てない
2. ノートに記録
3. 「ご指摘いただいた点、議事録に取って次フェーズで修正します」と返す
4. 会議後に修正

### 雇主から「これが違う」と言われたら
- 反論しない、まず「ご期待されていたのは…?」と聞き返す
- 弊社の解読を説明し、規格書のどこを根拠にしたか共有
- その場で結論出さなくて OK、議事録に「要相談」で OK

## 心得え

- 規格通り 100% 実装より「規格の意図を理解した上での提案」のほうが評価される
- 「全部できました!」より「ここはこう解読しましたが合っていますか?」のほうが信頼される
- 未完成項目を隠さない、DEMO.md に明記してある通りに正直に
- 質問が来たら回答より、まず「想定されているのは…?」で聞き返すクセ
